# test-first

一次只推进一个用例。红 → 绿 → 重构，三步都要有**可贴出来的输出**，不许口头声称。

## 适用

- 用：加一个新行为、修一个有复现步骤的 bug、给未覆盖的分支补网。
- 不用：纯文档/配置改动；连"期望行为"都还说不清的时候（先写清期望，再回来）。

## 步骤

1. **写清期望**：一句话说明"输入什么、应该输出什么"。说不清就先停，别写测试。
2. **写一个用例**：只写**一个**，名字用行为描述（`拒绝过期 token` 而不是 `test_auth_2`）。
3. **跑到红**：执行并**保留失败输出**。测试没红（直接过了）说明它没测到东西，重写。
4. **最小实现**：只写到这个用例通过，不提前实现下一个用例需要的东西。
5. **跑到绿**：跑**全量**测试，确认新用例过、旧用例不回归。
6. **重构**：在绿的状态下改结构，每改一步重跑一次。红了就退回上一步。

## 验收

- 有"红"的证据：失败输出里能看到断言差异，不是语法错误或 import 失败。
- 有"绿"的证据：全量测试通过，且**通过数比开始时多**（不是靠删改旧用例凑出来的）。
- 用例名能读懂行为；断言直接比期望值，不绕弯。
- 重构后测试代码与产品代码都没留下注释掉的死代码。

## 反例

- 先写实现再补测试，然后说"TDD 做的"——顺序错了，测试会照着实现的 bug 写。
- 一次写十个用例再一起跑：红了不知道是哪一个的需求。
- 把被测逻辑 mock 掉，测的是 mock 自己。
- 为了让测试过而改断言：断言是需求，不是障碍。
- 只跑单个文件就说"全绿"。
