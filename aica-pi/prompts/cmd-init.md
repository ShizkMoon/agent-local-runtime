读一遍仓库的目录结构、入口文件与已有文档，然后写一份 `AGENTS.md` 草稿（仓库根），只包含对后来的 agent 真正有用的事实，不要复述 README。

要求：
1. 项目一句话定位 + 技术栈（从 package.json / 锁文件 / 构建脚本里核实，不要猜）。
2. 构建 / 测试 / 类型检查的**确切命令**（从 scripts 里抄，标明工作目录）。
3. 目录职责表（每行：路径 → 负责什么），只写你实际打开看过证据的目录。
4. 代码约定（命名、错误处理、注释语言、测试放置），每条给一个真实文件路径作例证。
5. 禁区：不要写"待补充/TODO"，不要写没有证据的推断；不确定的事实标「待核」。

产出两处一致：`AGENTS.md` 落盘，并用 `ev_done` 的 summary 回传「写了哪些段、依据哪些文件」。
