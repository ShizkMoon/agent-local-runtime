## 0. 一页结论

**已经像 Codex/T3 的三件事**（别动）：审批卡（闭集 + fail-closed + 三动作 + 500ms 防误批 + 危险硬拒，比两家都严）、
工具时间线（一条命令一行、耗时/退出码/截断自证）、结论优先（结论块在过程之前，工具组折成统计行）。

**最不像的三件事**：① 工具行把参数当 JSON 裸奔（`bash {"command":"echo UI-OK"}`）；
② 右栏把同一句话说了 2–3 遍（标题/描述/再一遍）；③ 「进行中」的 run 可能已经死了 25 小时，界面还在转圈。

**Top 10 分档**：P0 四条（R5-01/02/05/06）、P1 三条（R5-03/04/07）、P2 三条（R5-08/09/10）。

**一句话**：现在的问题不是缺功能，是**同一条信息说得太多、最关键的那一行进不去眼**；
而这 10 条里有 3 条是**投影层（`view.ts`）的错**、不是 UI 的错——这说明"单源投影"这条架构是对的，只是还没把"用户读得懂"当成投影的验收项。

## 1. Top 10 问题

> 排序 = 离"顺手"差多远 × 修起来多便宜。每条给：截图定位 → 为什么伤可用度 → 改法 → 落点（文件:行 + 切片）。
> 行号按 `2026-11-04` 的 HEAD（`bdafb81` 之后、R4 未合入前）核对，改动后请以函数名为准。

### R5-01（P0）工具行把参数当 JSON 裸露

- **现状**：`shot-final-app.png` 中栏——`bash {"command":"echo UI-OK"}`、`bash {"command":"echo UI-OK > artifacts/ui.txt; echo \"exit=$?\"; cat artifa…"}`、`ev_done {"summary":"已执行 echo UI-OK …"}`。
- **为什么伤**：用户要读的是"这条命令干了什么"，现在读到的是**序列化格式的一半**（含 `{"command":` 与截断在词中间的 `artifa…`）。
  Codex / T3 的工具行都是人形：命令行、文件路径、`+N −M`。这是"像不像 CodingAgent"的分水岭（PRD §0 缺口 1）。
- **改法**：按 `kind` 出人形摘要——`bash`→命令行首行（去掉 `$SHELL -c` 包装）、`read/glob`→路径、`edit`→`文件 +N −M`、
  `ev_*`→摘要第一句、其余→`key=value` 拼接；原始 JSON 只在展开里。
- **落点**：`workbench/public/v1/index.html:1440`（`s.args` 直接 `esc()` 输出）、`workbench/view.ts` 的 `StepView`（加 `arg_text`，单源格式化）；切片 **R5-01**；关联 P2 / U07 / U08。成本 **S**。

### R5-02（P0）右栏卡片同一句话出现 2–3 次

- **现状**：`r4-02-delivery-three.png` 审批卡——标题「等你拍板：要不要删掉旧的 smoke 记录，决定删不删」+ 描述「旧 smoke 记录要不要一起删?」+ 第三行「旧 smoke 记录要不要一起删?」；
  `04-health.png` 背景卡同样：「键盘快捷键接线」+「申请执行：npm test（等你裁决）」+「请求执行：npm test（等你裁决）」。
- **为什么伤**：右栏是**一屏里信息密度最高**的地方，重复直接吃掉判断时间；也违反 P3/R1「一条信息只出现一次」——这是被自己定的规则打回。
- **根因**：`workbench/view.ts:1434` 的 inbox 投影 `t: q.split("\n")[0].slice(0,80), d: q` —— 单行问题时 `t` 与 `d` 完全相同；
  `gateCardHtml`（`index.html:1857-1858`）照单全收。审批卡的"请求执行/申请执行"是标题与描述又各拼了一次动作。
- **改法**：投影层保证 `d` 只在"比 `t` 多出信息"时非空；UI 层加一道保险（`d === t` 就不渲染）；审批卡标题只留动作（「执行命令」/「删除文件」），命令进 `<pre>`，理由进一行 `desc`。
- **落点**：`workbench/view.ts:1434` + `index.html:gateCardHtml / approvalCardHtml / proposalCardHtml`；切片 **R5-02**；关联 P3 / U19。成本 **S**。

### R5-03（P1）命令面板把 6 条命令埋在任务列表底下，且徽标是英文

- **现状**：`shot-palette.png`——9 行全是「打开任务：…」，每行右侧徽标 `done`；真正的命令（切密度/打开审批/派发/诊断/提案/子代理）
  要往下滚才出现（`palActions()` 先 `RUNS.forEach` push 全部任务，命令在后）。
- **为什么伤**：`Ctrl+K` 的价值是"不用记位置直达动作"，现在它退化成了"任务跳转器"；而 `/` 只聚焦输入框，
  所以**键盘用户的动作入口为零**。`done` 这类英文徽标还和全中文界面打架。
- **改法**：动作置顶并分组（`动作` / `任务` 两个小节标题）；任务行徽标走 `AGG_LABEL`（等你/失败/进行中/已完成）；
  可选：输入以 `>` 开头只搜命令。**不要**为此发明第二套 slash 语法规。
- **落点**：`index.html: palActions()`（≈2333 行起）、`renderPalette()`；切片 **R5-03**；关联 P15 / U23 / U24。成本 **S**。

### R5-04（P1）左栏「已结束」被同名 smoke run 淹没

- **现状**：`shot-final-app.png` 左栏——`smoke-e2e` 出现 6 次（16:14/16:13/16:13/16:12/04:55/…）、`smoke-tools` 2 次、
  「用 bash 执行 echo …」2 次；行内只有 `pill + 时长 + title + snippet`，同名时**唯一区分信息是时间戳**。
- **为什么伤**：真任务（`把 view 投影抽成纯函数…`）被 6 行噪声挤到看不见；用户开始不看左栏。
  R3 的「测试」分组只解决"测试 run 混在已结束里"，没解决"同名 run 之间不可辨识"。
- **改法**：同名 run 折叠成一组（`smoke-e2e ×6`，点开展开）；或行内带 `run id` 后 4 位短码 + 时长差异；
  已结束区默认只显示最近 10 条 + 「显示全部」。
- **落点**：`index.html: renderSidebar() / runCardHtml()`（≈1091、1107 行）；切片 **R5-04**；关联 P5 / PRD §5.1。成本 **M**。

### R5-05（P0）「进行中」的 run 可能早就死了

- **现状**：`shot-final-app.png` 左栏 `smoke test · 1500:03`——25 小时前的 run 仍是「进行中」绿点；
  `shot-palette.png` 同一行已变成 `1559:00`（又 1 小时）。全仓没有任何 run 级 staleness 判据（`st-stale` 只用于提案）。
- **为什么伤**：B3「可恢复是默认值」要求界面与磁盘真相同构；现在磁盘上明明没有 worker 在跑，界面却说"进行中"，
  用户只能自己怀疑"是不是卡了"——这正是 P8「等待与失败没有形状」的第 2 次打回。
  **对照**：Codex 在 `gate-req` 超 60s 未答时就会变色，且超时记 `timeout` 而不是 `deny`（`codex.md` §4 结论 3）；
  我们连 25 小时的 run 都不变色。
- **改法**：`view.ts` 给 RunView 加 `idle_ms`（= now − 最后一条事件/worker 心跳）；UI 在 `idle_ms > 10min` 时把状态词改成
  「疑似卡死 · 25h 无新事件」，行尾给「重试 / 中止」两个动作（`apiRetry`/`apiAbort` 已有）。
- **落点**：`workbench/view.ts`（`RunView` + 投影）、`index.html: pillOf()/setStatusWord()/statusLineHtml()`；切片 **R5-05**；关联 P5 / P8 / B3。成本 **M**。

### R5-06（P0）审批卡的破坏性动作没有视觉权重（危险色是死代码）

- **现状**：`r4-02-delivery-three.png` 的「删 / 留着」、`04-health.png` 的「同意 / 拒绝」——四个按钮**同一种浅色描边**，
  破坏性动作既不红也不写后果；`gateCardHtml` 里明明有 `danger` / `solid` 两个分支。
- **根因**：`workbench/view.ts:1434` 的 opts 三元组第二项永远是空串（`[["同意","","已同意"], ["拒绝","","已拒绝"]]`），
  于是 `index.html:1860` 的 `{"danger":1,"solid":1}[o[1]]` 永远拿不到值——**危险色渲染是死代码**。
- **改法**：投影层按 op 语义填 kind：`拒绝/删除/中止` → `danger`；推荐项（留着/允许一次）→ `solid`；
  危险项的文案带后果（「删除 2 条记录，不可恢复」）。
- **落点**：`workbench/view.ts:1434-1436`（opts 构造）、`index.html:gateCardHtml`；切片 **R5-06**；关联 P10 / U13 / U25。成本 **S**。

### R5-07（P1）设置面板与健康弹层是两种容器，且设置会遮住「需要你」

- **现状**：`shot-r4-settings.png`——设置是**右栏 sheet**，打开时整块决策队列被替换成设置项（同屏已没有审批卡）；
  `04-health.png`——健康检查是**居中 modal**。同一类"系统面"两种容器。
- **为什么伤**：P1 说右栏 = 决策队列；设置占用它意味着"用户一进设置就看不见待裁决"。
  两个面板的关闭语义也不同（右栏 Esc 恢复原页签 vs modal Esc 关闭），用户要记两套。
- **改法**：设置改居中 modal（与健康一致）；或设置保留 sheet 但在头部保留「需要你 N」的跳回入口，关闭后恢复原页签。
- **落点**：`index.html: #settings`（≈3004 行）/ `openHealth()`（≈2276 行）/ `switchPane()`；切片 **R5-07**；关联 P1 / P17。成本 **S**。

### R5-08（P2）设置项把字段名当值显示

- **现状**：`shot-r4-settings.png`「并发上限：`run.json.parallel` 默认」——左边是 JSON 字段路径，右边是"默认"。
- **为什么伤**：用户会以为值坏了；设置面板里露出内部字段名，等于承认"这行是占位"。
- **改法**：显示「默认 2（当前 run 未指定）」；`run.json.parallel` 收进说明小字或 tooltip。
- **落点**：`index.html:3004-3006`（`.set-kv` 那一行）；切片 **R5-08**；关联 P19 / R4 设置面板。成本 **XS**。

### R5-09（P2）字号 14 档、间距只有 42% 落在 4 的倍数上

- **现状**（脚本量的）：字号 14 个取值，含 **6 个半像素档**（10.5/11.5/12.5/13.5/14.5/15.5），`12px` 用了 58 次、`13px` 21 次、
  `12.5px` 13 次——三级"说明文字"并存；间距里 4 的倍数 81 处、2 的倍数但非 4（6/10/14/18）73 处、**奇数值 39 处**（1/3/5/7/9/11）。
- **为什么伤**：P7 写的"写死 4/8/12/20"没有执行；半像素档在 100% 缩放下会糊，对齐靠眼调，改一处动全身。
- **改法**：字号收敛到 5 档（11 / 12.5 / 13.5 / 15 / 18），间距收敛到 4/8/12/20（2 只作细分）；
  加一条 20 行的 node 检查脚本进 `workbench/test`，非刻度值直接 fail。
- **落点**：`index.html` 全局 CSS（token 块 + 各组件）；切片 **R5-09**；关联 P7 / P19。成本 **M**（纯 CSS，但面广）。

### R5-10（P2）键盘焦点不可见

- **现状**（脚本量的）：全文件 `:focus-visible` 只有 **3 条**规则、`outline:none` **5 处**、`:focus` 3 条。
  palette 行、审批卡按钮、工具行按钮都没有统一 focus ring。
- **为什么伤**：`Ctrl+K` → `J/K` → `A/R` 这条主路径（P15）全靠焦点可见；看不见焦点等于快捷键只能盲按。
- **改法**：全局 `:focus-visible{outline:2px solid var(--accent);outline-offset:2px}`，删掉裸 `outline:none`；
  容器用 `:focus-within` 给一条内描边。
- **落点**：`index.html` CSS（≈原来 5 处 `outline:none` 的位置）；切片 **R5-10**；关联 P15 / U23 / U24。成本 **S**。

## 2. Codex / T3 能力对照（8 行）

| **焦点态** | composer：可见焦点 + Enter 提示 | palette 行/卡片按钮无统一 ring | `:focus-visible` 3 条、`outline:none` 5 处 |
| **空态** | 右栏「这个 run 没有待裁决项 / 审批与提问会出现在这里，回答后自动折叠 / **下一步**…」（U19 达标） | 左栏「暂无运行中的任务」、产物「暂无产物」、子代理「无下级子代理」——都是"暂无 X"一句话 | 空态渲染点 24 处，只有 **2 处**用 `.empty-2`（"为什么 + 怎么做"结构），字面写「下一步」的只有 1 处 |
| **加载态** | 等待态一行 shimmer「正在运行 bash · 12s」，reduced-motion 退化为静态（S25/U10/U26） | **没有骨架屏**（`skeleton` 0 处）；切 run 期间旧内容原地不动，看不出"正在换" | 首屏实测 195ms（所以只是观感，不是性能） |
| **错误态** | 失败行 = 红点 + 一句人话 + 「详见节点 events.jsonl」，不假装成功 | 诊断页把「daemon 没在跑」标成红色——**本地闲置是正常态**，红点制造假警报 | `--fig` 同时用于"错误"与"失败 run"，语义被合并 |

**这节的两个结论**：① 对比度问题只出在**一个 token**（`--warn` 亮底），改一个值就能过 U25；
② 空态/错误态的毛病都是"**没有说下一步**"或"**把正常态标成错误**"，属于文案与语义，不是视觉。

## 4. 不要做的事（防止为了"像"而堆功能）

1. **不加 slash 命令语法**。我们有 palette；T3 也没有 slash。先把 `palActions()` 排序修好（R5-03），别造第二套入口。
2. **不做多 provider 切换**（T3 有）。pi 单引擎够用，PRD §1.4 已判定"进 R3 再议"；现在做等于给每个 provider 重新做一遍审批映射。
3. **不抄 MCP 工具目录预算**（OpenCode/Codex 有）。R4 的 MCP 还没开工，先做工具来源校验，别先做预算。
4. **不给 diff 加"接受/回滚"按钮**，除非 checkpoint 先有可见入口——否则就是 P20 说的"假承诺"。
5. **不做第 3 档 verbosity、不做 pane-tab 终端复用、不做 docking、不做自动滚动抢占**（P20 原文，一条都不要破）。
6. **不做 TUI / 键盘独占路径**。每个快捷键必须有鼠标等价入口（P15/U24），别为了"像 Codex"砍鼠标路径。
7. **不在设置面板里放"只读展示"当设置项**（R5-08 的反面）；设置只放**改了会生效**的东西。
8. **不加第五种语义色**。现在四色（红/琥珀/灰/蓝）已经够；`--warn` 只是对比度不够，不是缺颜色。
